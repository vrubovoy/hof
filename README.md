# Hof

Небольшой набор веб-приложений для себя, семьи или небольшой группы людей на своём сервере.
Что это и зачем — [PRODUCT.md](PRODUCT.md), как устроено — [ARCHITECTURE.md](ARCHITECTURE.md).

## Разработка

Нужны Node.js 24.12 или новее с npm и Docker с Compose (на macOS — например, colima).
Сборки нет: Node запускает `.ts` напрямую, удаляя типы.

Один раз — конфигурация и база для разработки:

```sh
cp .env.example .env && chmod 600 .env   # заполнить пароли: openssl rand -hex 24
docker compose -f compose.dev.yaml up -d # PostgreSQL 18 на 127.0.0.1:5433
```

Кроме паролей в `.env` задают установку: `CURRENCY` — валюту сумм Säckel (код ISO 4217 с двумя
знаками после запятой, например `RUB`) и `TZ` — часовой пояс «сегодня» (например
`Europe/Moscow`). Без них или с неверным значением сервер не стартует и называет переменную.
Валюту фиксирует первая запись: если в базе уже есть записи в другой валюте, сервер тоже не
стартует — смена валюты не поддерживается.

Контейнер создаёт базы `hof` (для `npm run dev`) и `hof_test` (для тестов), роли `hof_core` и
`hof_saeckel` и их схемы — скриптом `deploy/postgres-init.sh`. Скрипт выполняется только на
пустом томе; после его изменения том пересоздают:

```sh
docker compose -f compose.dev.yaml down -v && docker compose -f compose.dev.yaml up -d
```

Порт 5433 выбран, чтобы не мешать локально установленному PostgreSQL на 5432. Сервер и тесты
находят его через стандартную переменную `PGPORT` из `.env`.

```sh
npm ci          # зависимости строго по package-lock.json
npm run dev     # сервер на http://localhost:3000, перезапуск при изменении файлов
npm run check   # prettier --check, eslint, tsc --noEmit, node --test, docker compose build
npm run format  # отформатировать всё через prettier
```

`npm run check` должен проходить перед каждым коммитом; тестам нужна запущенная база.

При старте сервер применяет новые миграции (`src/<модуль>/migrations/NNN_*.sql`) к базе `hof` и
только потом открывает порт: сначала Core под ролью `hof_core`, затем Säckel под ролью
`hof_saeckel`. Строка `info start` перечисляет применённые файлы с именем модуля
(`saeckel/001_pouches.sql`). Säckel открывается со Двора, адрес — `/saeckel/`. Тесты работают с
`hof_test` и выполняются последовательно.

### Первый запуск в браузере (localhost)

Пока Хозяина нет, сервер при старте пишет в лог строку `info gate_key key=XXXXX-XXXXX-XXXXX-XXXXX`.
Любой адрес ведёт на `/setup`; после основания двора `/` открывает Двор.

Cookie сессии — `__Host-hof` с `Secure`. По HTTP её принимают только браузеры, которые считают
`http://localhost` безопасным, а форма работает, только если браузер присылает на POST заголовок
`Origin`. Как проверить браузер: `npm run dev`, открыть `http://localhost:3000`, ввести ключ из лога,
логин и пароль.

- Открылся Двор — `Origin` пришёл, cookie принята.
- «Запрос отклонён» (403) — браузер не прислал `Origin`.
- Переход на `/login` после основания — cookie не принята.

Чтобы пройти первый запуск заново, Хозяина и сессии в dev-базе удаляют:

```sh
docker compose -f compose.dev.yaml exec postgres psql -U postgres -d hof -c 'TRUNCATE core.sessions, core.users RESTART IDENTITY'
```

| Браузер                                          | Дата       | `Origin` на POST | `__Host-hof` Secure на `http://localhost`                                                               |
| ------------------------------------------------ | ---------- | ---------------- | ------------------------------------------------------------------------------------------------------- |
| Chromium 152 (встроенный браузер Claude Desktop) | 2026-10-12 | приходит         | принимается; из JavaScript не видна (`HttpOnly`)                                                        |
| Google Chrome 154                                | 2026-10-12 | приходит         | принимается                                                                                             |
| Firefox                                          | 2026-10-12 | приходит         | принимается                                                                                             |
| Safari 26.3                                      | 2026-10-12 | приходит         | не принимается (после основания — переход на `/login`); Safari проверяется по HTTPS после развёртывания |

### Вход и выход в браузере (localhost)

После основания двора:

1. Открыть `/?a=1` без сессии — переход на `/login?next=%2F%3Fa%3D1`.
2. Неверный пароль — «Неверный логин или пароль.», логин остаётся в поле, пароль стёрт.
3. Верный пароль — снова `/?a=1`.
4. `/login?next=%2F%2Fevil.example` с живой сессией ведёт на `/`, а не на чужой сайт.
5. «Покинуть двор» — `/login`. «Назад» после выхода не должен показать Двор: браузер заново
   запрашивает `/` и попадает на `/login?next=%2F`.

| Браузер                                          | Дата       | Шаги 1–5 | «Назад» после выхода                     |
| ------------------------------------------------ | ---------- | -------- | ---------------------------------------- |
| Chromium 152 (встроенный браузер Claude Desktop) | 2026-10-12 | работают | Двор не показан: `/` → `/login?next=%2F` |

### Production compose локально

`compose.yaml` — то, что будет работать на сервере: `postgres` и `hof` из образа по `Dockerfile`.
Пароли берутся из того же `.env`; каждый контейнер получает только свои.

```sh
docker compose up -d --build  # собрать образ hof и запустить оба контейнера
docker compose logs hof       # строка `info start` и применённые миграции
docker compose stop           # остановить; контейнеры и данные остаются
docker compose start          # запустить остановленные контейнеры снова
docker compose down           # удалить контейнеры; том с данными остаётся
```

Наружу порты пока не открыты, сервер виден только внутри сети compose. Данные лежат в томе
`hof_pgdata`, отдельно от dev-тома `hof-dev_pgdata`, так что обе базы могут работать одновременно.
`docker compose down -v` удаляет и этот том со всеми записями, поэтому для production эта команда
не используется.

Контейнеры поднимаются сами (`restart: unless-stopped`) после падения процесса и после перезапуска
Docker — на Mac, значит, вместе с colima, — но не после `docker compose stop`. `hof` останавливается
сразу: первым процессом в контейнере работает init Docker (`init: true`), он передаёт SIGTERM в
Node. Docker хранит логи каждого контейнера в трёх файлах по 10 МБ, старые строки уходят.

#### Лимиты памяти для маленького сервера

`deploy/compose.limits.yaml` ограничивает память контейнеров на сервере, где Hof делит небольшую
память с другими сервисами. В стандартную установку он не входит: `compose.yaml` лимитов не задаёт.
Файл действует, только если в `.env` этого сервера есть строка

```
COMPOSE_FILE=compose.yaml:deploy/compose.limits.yaml
```

и `docker compose` запускается из каталога Hof. Проверить, что лимиты применились:
`docker compose config` показывает `mem_limit` и `memswap_limit`, а
`docker inspect --format '{{.HostConfig.Memory}} {{.HostConfig.MemorySwap}}' <контейнер>` — два
одинаковых числа.

`memswap_limit` равен `mem_limit`, поэтому контейнер не получает swap; swap самого сервера не
меняется. Если контейнер упирается в лимит, ядро завершает процесс только внутри него: сервер Hof
Docker перезапускает вместе с контейнером, а потерянный процесс PostgreSQL база восстанавливает
сама. Это снижает риск, что Hof помешает соседним сервисам, но не гарантирует им память: сборка
образа, кэш файлов, ядро и сами соседи лимитами не ограничены. Значения — замеренный пик каждого
контейнера с запасом; в лимит `hof` входит и `docker compose exec hof node src/cli.ts`, потому что
команда работает в том же контейнере.

Код сервера — в `src/`, тесты лежат рядом с кодом (`*.test.ts`). В TypeScript допустим только
синтаксис, который Node может просто стереть: без `enum`, `namespace` с кодом, parameter
properties и декораторов (ARCHITECTURE.md §7) — `tsc` такие конструкции отклоняет.

`design/` — утверждённый визуальный эталон и исходники картинок и звуков, а не код сервера.

## Восстановление доступа

Пароль приближённого сбрасывает Хозяин: «Приближённые» → «Открыть ›» → «Сбросить пароль».
Если пароль забыл сам Хозяин, новый задают на сервере:

```sh
docker compose exec hof node src/cli.ts reset-password <логин>
```

В разработке — против dev-базы:

```sh
node --env-file=.env src/cli.ts reset-password <логин>
```

Команда спрашивает новый пароль дважды; набранное на экране не видно. Правила те же, что в
форме: не короче 15 символов, повтор должен совпасть. После сброса все сессии этого человека
завершаются, войти можно только с новым паролем. Отключённый пользователь остаётся отключённым.

Пароль вводится только с клавиатуры: аргументом, через переменную окружения или из перенаправленного
ввода (`< файл`, `|`, `docker compose exec -T`) команда его не примет и откажется работать. Ctrl+C
отменяет сброс, ничего не меняя. Строка `info password_reset` печатается в этом же терминале, в
`docker compose logs` её нет: команда — отдельный процесс.
