# Hof

Небольшой набор веб-приложений для себя, семьи или небольшой группы людей на своём сервере.
Что это и зачем — [PRODUCT.md](PRODUCT.md), как устроено — [ARCHITECTURE.md](ARCHITECTURE.md),
установка и обслуживание сервера — [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Требования

- Разработка: Node.js 24.12 или новее с npm и Docker с Compose (на macOS — например, colima).
- Сервер: Linux с Docker Engine и Compose v2, `git`, `openssl` и `certbot`, домен с A-записью на
  IPv4 сервера, свободные порты 80 и 443. Hof с PostgreSQL и nginx занимает около 0,7 ГБ диска и
  в простое меньше 100 MiB памяти; замеры и пороги — [docs/OPERATIONS.md](docs/OPERATIONS.md).

## Установка на сервер

Кратко; команды и проверки каждого шага — в разделе «Установка» [docs/OPERATIONS.md](docs/OPERATIONS.md):

1. A-запись домена указывает на сервер, порты 80 и 443 свободны.
2. Код Hof — в `/opt/hof`, на проверенном теге.
3. `.env` с паролями, валютой, часовым поясом и доменом, права 600.
4. Сертификат Let's Encrypt — certbot на хосте, до первого запуска.
5. `docker compose up -d --build`; проверка ролей базы и сертификата, который отдаёт nginx.
6. Хуки продления сертификата.
7. Основание двора ключом из лога `hof`.

## Разработка

Сборки нет: Node запускает `.ts` напрямую, удаляя типы.

Один раз — конфигурация и база для разработки:

```sh
cp .env.example .env && chmod 600 .env   # заполнить пароли: openssl rand -hex 24
docker compose -f compose.dev.yaml up -d # PostgreSQL 18 на 127.0.0.1:5433
```

Кроме паролей в `.env` задают установку: `CURRENCY` — валюту сумм Säckel (код ISO 4217 с двумя
знаками после запятой, например `RUB`) и `TZ` — часовой пояс «сегодня» (например
`Europe/Moscow`). Без них или с неверным значением сервер не стартует и называет переменную.
Валюту фиксирует первая запись: если в базе уже есть записи в другой валюте, сервер тоже не
стартует — смена валюты не поддерживается.

Контейнер создаёт базы `hof` (для `npm run dev`) и `hof_test` (для тестов), роли `hof_core` и
`hof_saeckel` и их схемы — скриптом `deploy/postgres-init.sh`. Скрипт выполняется только на
пустом томе; после его изменения том пересоздают:

```sh
docker compose -f compose.dev.yaml down -v && docker compose -f compose.dev.yaml up -d
```

Порт 5433 выбран, чтобы не мешать локально установленному PostgreSQL на 5432. Сервер и тесты
находят его через стандартную переменную `PGPORT` из `.env`.

```sh
npm ci          # зависимости строго по package-lock.json
npm run dev     # сервер на http://localhost:3000, перезапуск при изменении файлов
npm run check   # prettier --check, eslint, tsc --noEmit, node --test, docker compose build
npm run format  # отформатировать всё через prettier
```

`npm run check` должен проходить перед каждым коммитом; тестам нужна запущенная база.

При старте сервер применяет новые миграции (`src/<модуль>/migrations/NNN_*.sql`) к базе `hof` и
только потом открывает порт: сначала Core под ролью `hof_core`, затем Säckel под ролью
`hof_saeckel`. Строка `info start` перечисляет применённые файлы с именем модуля
(`saeckel/001_pouches.sql`). Säckel открывается со Двора, адрес — `/saeckel/`. Тесты работают с
`hof_test` и выполняются последовательно.

### Первый запуск в браузере (localhost)

Пока Хозяина нет, сервер при старте пишет в лог строку `info gate_key key=XXXXX-XXXXX-XXXXX-XXXXX`.
Любой адрес ведёт на `/setup`; после основания двора `/` открывает Двор.

Cookie сессии — `__Host-hof` с `Secure`. По HTTP её принимают только браузеры, которые считают
`http://localhost` безопасным, а форма работает, только если браузер присылает на POST заголовок
`Origin`. Как проверить браузер: `npm run dev`, открыть `http://localhost:3000`, ввести ключ из лога,
логин и пароль.

- Открылся Двор — `Origin` пришёл, cookie принята.
- «Запрос отклонён» (403) — браузер не прислал `Origin`.
- Переход на `/login` после основания — cookie не принята.

Чтобы пройти первый запуск заново, Хозяина и сессии в dev-базе удаляют:

```sh
docker compose -f compose.dev.yaml exec postgres psql -U postgres -d hof -c 'TRUNCATE core.sessions, core.users RESTART IDENTITY'
```

| Браузер                                          | Дата       | `Origin` на POST | `__Host-hof` Secure на `http://localhost`                                                               |
| ------------------------------------------------ | ---------- | ---------------- | ------------------------------------------------------------------------------------------------------- |
| Chromium 152 (встроенный браузер Claude Desktop) | 2026-10-12 | приходит         | принимается; из JavaScript не видна (`HttpOnly`)                                                        |
| Google Chrome 154                                | 2026-10-12 | приходит         | принимается                                                                                             |
| Firefox                                          | 2026-10-12 | приходит         | принимается                                                                                             |
| Safari 26.3                                      | 2026-10-12 | приходит         | не принимается (после основания — переход на `/login`); Safari проверяется по HTTPS после развёртывания |

### Вход и выход в браузере (localhost)

После основания двора:

1. Открыть `/?a=1` без сессии — переход на `/login?next=%2F%3Fa%3D1`.
2. Неверный пароль — «Неверный логин или пароль.», логин остаётся в поле, пароль стёрт.
3. Верный пароль — снова `/?a=1`.
4. `/login?next=%2F%2Fevil.example` с живой сессией ведёт на `/`, а не на чужой сайт.
5. «Покинуть двор» — `/login`. «Назад» после выхода не должен показать Двор: браузер заново
   запрашивает `/` и попадает на `/login?next=%2F`.

| Браузер                                          | Дата       | Шаги 1–5 | «Назад» после выхода                     |
| ------------------------------------------------ | ---------- | -------- | ---------------------------------------- |
| Chromium 152 (встроенный браузер Claude Desktop) | 2026-10-12 | работают | Двор не показан: `/` → `/login?next=%2F` |

### Облик и его проверка

Static каждого модуля лежит в его папке: Core — `src/core/static/` (`hof.css`, `fonts/`, `img/`),
адреса `/static/…`; Säckel — `src/saeckel/static/` (`saeckel.css`, `fonts/`, `img/`), адреса
`/saeckel/static/…`. Общей папки нет: шрифт, бумага, перо и плашки у Säckel — свои копии, а его
страницы и CSS называют только файлы своей папки. В шрифтах Säckel есть ещё подмножество latin-ext
со знаком ₽ (EB Garamond той же версии, что у Core). Картинки — побайтные копии из `design/` с теми
же именами. Список файлов сервер составляет при старте, поэтому новый файл появляется только после
перезапуска `npm run dev`.

Прототипы из `design/preview/` открывают рядом с сервером (шрифт прототипы берут с Google Fonts):

```sh
python3 -m http.server 8765 --bind 127.0.0.1   # из корня репозитория
```

Затем `http://localhost:8765/design/preview/index.html` и тот же экран на
`http://localhost:3000`, в окне 1440×900 и в режиме телефона 390×844 (DevTools, Device Toolbar).
Прототип вписывает экран в окно, поэтому окно должно быть ровно этого размера.

Страницы ошибок:

- 404 — любой неизвестный адрес, например `/nope`;
- 403 — войти не Хозяином и открыть `/admin/users`;
- 500 — с живой сессией остановить базу (`docker compose -f compose.dev.yaml stop postgres`) и
  открыть `/`: страница с «Попробовать ещё раз»; отправка формы, например «Покинуть двор», — та же
  страница без этой кнопки. Потом `docker compose -f compose.dev.yaml start postgres`; записи в
  базе от этого не меняются.

Экраны Säckel и их прототипы:

- Мешки — `Saeckel`, `SaeckelMobile`, `SaeckelEmpty`, `SaeckelEmptyMobile`;
- мешок и «Изменить» — `Saeckel` (справа), `PouchMobile`, `PouchEditMobile`;
- «Доход», «Переложить», «Новый мешок» и запись — `SaeckelForms`, на телефоне `IncomeMobile`;
- «Разложить» — `SaeckelAssign`, `AssignMobile`;
- Летопись — `SaeckelHistory`, `HistoryMobile`, `SaeckelHistoryEmpty`.

Прототипов нет у мешка из Кладовой, у «Разложить» без мешков и с отказом всей формы, у записи
мешка из Кладовой, у Летописи по мешку без записей и у страницы за последней: они собраны из тех
же материалов. Состояния удобно смотреть под отдельным пользователем:

- пустые экраны — у пользователя без мешков и записей;
- ошибки форм — отправить сумму `0` или `x`, дату `31.02.2026`, пустой выбор мешка;
- три страницы Летописи — 120 записей одним `INSERT … generate_series`, как в
  `src/saeckel/look.test.ts`;
- Кладовая — мешок с нулевым остатком убрать «В кладовую»: его записи открываются только для
  чтения, правка и удаление отвечают 400.

`look.test.ts` обходит все страницы Säckel в этих состояниях и проверяет то, что видно в HTML:
адреса static, один `h1`, уникальные `id`, связи ошибок с полями, одну ссылку на запись Летописи.

Вручную остаются проверки, которых нет в тестах: экраны рядом с прототипами, Tab и видимый
фокус, масштаб 200 %, Firefox и Safari. Safari не принимает cookie сессии на `http://localhost`
(таблица выше), поэтому локально в нём проверяют только вход, основание и 404, а остальное — по
HTTPS после развёртывания, вместе с Safari на iPhone. Для Säckel там отдельно смотрят то, что
рисует сам браузер: раскрытие списков выбора, «Удалить» в `<details>`, строки Летописи как ссылки
и поля дат и сумм с экранной клавиатурой.

### Production compose локально

`compose.yaml` — то, что будет работать на сервере: `nginx`, `postgres` и `hof` из образа по
`Dockerfile`. Пароли берутся из того же `.env`; каждый контейнер получает только свои.

Локально сертификата нет, поэтому запускают только `postgres` и `hof`. `HOF_DOMAIN` для этого не
нужен: его читает только `nginx`. Без `HOF_DOMAIN` полный `docker compose up` создаёт `postgres` и
`hof`, а на `nginx` останавливается: Docker сообщает, что нет каталога
`/etc/letsencrypt/live/set-HOF_DOMAIN-in-.env`.

```sh
docker compose up -d --build postgres hof  # собрать образ hof и запустить оба контейнера
docker compose logs hof                    # строка `info start` и применённые миграции
docker compose stop                        # остановить; контейнеры и данные остаются
docker compose start                       # запустить остановленные контейнеры снова
docker compose down                        # удалить контейнеры; том с данными остаётся
```

`postgres` и `hof` портов наружу не открывают, их видно только внутри сети compose; на сервере
снаружи доступен только `nginx` на 80 и 443 по IPv4. Данные лежат в томе
`hof_pgdata`, отдельно от dev-тома `hof-dev_pgdata`, так что обе базы могут работать одновременно.
`docker compose down -v` удаляет и этот том со всеми записями, поэтому для production эта команда
не используется.

Пароль в dev-базе сбрасывают той же командой, что на сервере (раздел «Восстановление доступа»
[docs/OPERATIONS.md](docs/OPERATIONS.md)), но без контейнера:

```sh
node --env-file=.env src/cli.ts reset-password <логин>
```

Код сервера — в `src/`, тесты лежат рядом с кодом (`*.test.ts`). В TypeScript допустим только
синтаксис, который Node может просто стереть: без `enum`, `namespace` с кодом, parameter
properties и декораторов (ARCHITECTURE.md §7) — `tsc` такие конструкции отклоняет.

`design/` — утверждённый визуальный эталон и исходники картинок и звуков, а не код сервера.
