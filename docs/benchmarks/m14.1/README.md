# Базовые серии M14.1

Исходные файлы серий замера M14.1 (docs/OPERATIONS.md, «Замер скорости страниц», «M14.1: базовая
линия M13») — доказательная база сравнения прототипов M14. Сняты 2026-11-26 скриптом
`src/measure.ts` на MacBook arm64 от сети, Chrome 158.0.8127.88, Node v24.22.1, по 10 прогонов
после прогревочного, сценарий `full`, на тестовом дворе скрипта в базе разработки.

| Файл         | Версия             | Части                           | Порядок |
| ------------ | ------------------ | ------------------------------- | ------- |
| `m13-1.json` | тег `m13`, 613d70b | документы, путь, музыка, память | первая  |
| `m12.json`   | тег `m12`, 1c38529 | документы, путь                 | вторая  |
| `m13-2.json` | тег `m13`, 613d70b | документы, путь                 | третья  |

Проверочные серии после исправлений ревью M14.1 — тот же сервер M13, по 2 прогона, новой версией
скрипта: `check-full.json` (сценарий `full`: путь и музыка) и `check-nav.json` (`navigation`:
путь, музыка, память). Это не базовая линия: они подтверждают новые поля на M13.

Отчёт:

```sh
node src/measure.ts --report docs/benchmarks/m14.1/m13-1.json docs/benchmarks/m14.1/m12.json docs/benchmarks/m14.1/m13-2.json
```

## Что в файлах

Серия — JSON скрипта как есть (`Series` в `src/measure.ts`): версия Chrome и Node, флаги Chrome,
адреса файлов статики с версиями (какая сборка измерена), отпечаток данных (колонка мешков
тестового двора), все прогоны всех частей. Ни паролей, ни cookie, ни ключа от ворот, ни данных
людей в них нет: только тестовый двор и показания браузера. Проверено перед сохранением.

Отличия от файлов, которые записал скрипт:

- **Питание** сокращено до источника и заряда («сеть 32 %»): `pmset` называл и номер батареи этого
  компьютера. Так же теперь записывает сам скрипт.
- **`m13-1.json` собран из двух запусков.** Первый (документы, путь, музыка) остановился на восьмом
  прогоне музыки из-за сбоя скрипта при запуске Chrome, исправленного тогда же; музыка и память
  сняты вторым запуском на том же сервере сразу после. Из первого взяты документы и путь, из
  второго — музыка и память; дата и питание в начале — первого запуска, в конце — второго.

## Поля до исправлений ревью M14.1

Серии сняты до исправлений ревью M14.1. Изменились обозначения, а не замеры:

- **`newDocument`** вместо `document`. `true` — новый документ; `false` — страница из
  back/forward cache: M13 и M12 рисуют вид без нового документа только при `pageshow` с
  `persisted` (`performance.mark('hof:view')` в них нет), и `false` стоит только у «Назад».
  Отчёт читает `false` как «bfcache». Проверочные серии с полем `document` это подтверждают: у M13
  «Назад» — back/forward cache во всех прогонах, остальные шаги — новый документ.
- **`requests.repeated`** — любой повтор того же метода и адреса в шаге; `replaced` и `data` нет.
  В отчёте такая ячейка помечена «*». В базовых сериях повтор был только у выхода с «Анимациями»;
  проверочные серии разделяют его: лишних повторов 0, один повтор после отмены (документ входа,
  запрошенный снова после отменённого), один отменённый запрос.

## Музыка телефона в проверочной серии `full`

Тишина на телефоне в обоих прогонах `check-full.json` — от 1,5 до 7 с и растёт к концу пути, выше,
чем в медианах `m13-1.json`. Код замера музыки исправления не меняли. Музыка M13 на телефоне от
прогона к прогону двоится и в базовой серии: часть прогонов — около 0,2 с на каждом шаге, часть —
1–4,6 с, иногда растущие к концу пути (прогон 2 в обоих запусках первой серии). Вероятная причина —
новый документ загружает музыку заново по медленной сети; это не проверялось. Два прогона этот
разброс не оценивают, а порог музыки для прототипов абсолютный (0 новых плееров, 0 мс тишины),
поэтому базовая музыка не переснималась.
